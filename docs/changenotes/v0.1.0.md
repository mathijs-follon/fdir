# v0.1.0

Initial release of `fdir`, a portable C11 FDIR (Fault Detection, Isolation and Recovery) library for embedded and RTOS applications.

[README](https://github.com/mathijs-follon/fdir/blob/main/README.md) | [API reference](https://github.com/mathijs-follon/fdir/blob/main/docs/api.md)

## What is included

**Core library (`libfdir.a`)**

- Entity registration with configurable restart budgets and watchdog heartbeat supervision
- Fault reporting and configurable recovery actions: restart, degrade, safe mode, reboot
- Subsystem registration with critical-path escalation to safe mode
- Explicit NOMINAL, DEGRADED, SAFE, and REBOOT_PENDING operating modes
- Five weak-symbol port hooks for platform integration with no OS dependency and no dynamic allocation

**C++ API (`include/fdir.hpp`)**

- Header-only wrapper compatible with C++20 and C++23
- RAII entity and subsystem handles
- Port hooks supplied as a struct of lambdas via `fdir::Supervisor::create()`
- `fdir::Expected<T,E>` backed by `std::expected` on C++23, built-in shim on C++20
- Full `enum class` wrappers for all C enumerations

**Examples**

Each example ships with a C (`c/`) and C++ (`cxx/`) variant:

- `getting_started`: minimal single-file example covering fault/restart, budget exhaustion, and watchdog detection
- `filecopy`: parallel directory copy CLI demonstrating multi-entity registration and fault-driven restart on I/O errors
- `FreeRTOS`: integration with the FreeRTOS POSIX/Linux simulator covering watchdog miss, budget exhaustion, and dual-path safe mode

**Tests and build**

- Unit tests for config, health, internal, port, recovery, report, and subsystem modules
- `compile_commands.json` generation for all source groups
- CI workflow building the library, running tests, and building all six example binaries

**Important Note:** 

You might want to build the library yourself and optimize for speed / size depending on your usecase. You could use `-Os -ffunction-sections -fdata-sections` as compile flags and link with `-Wl,--gc-sections` This keeps the library small and lets the linker remove anything the application does not actually call.
