# v1.0.1

Bug-fix release. No API changes.

[README](https://github.com/mathijs-follon/fdir/blob/main/README.md) | [API reference](https://github.com/mathijs-follon/fdir/blob/main/docs/api.md)

## Bug fixes

**Reject `FDIR_ACTION_RESTART` as `on_exhausted` ([#1](https://github.com/mathijs-follon/fdir/issues/1))**

If `restart()` failed, `apply_action()` recursed into `on_exhausted`. When that field was also `FDIR_ACTION_RESTART`, a failing restart callback caused unbounded recursion and stack overflow instead of bounded recovery.

- `fdir_entity_register()` now returns `FDIR_ERR_PARAM` when `on_exhausted == FDIR_ACTION_RESTART`
- `apply_action()` treats `FDIR_ACTION_RESTART` as `FDIR_ACTION_NONE` on the restart-failure fallback path

**Atomic critical fault reporting ([#2](https://github.com/mathijs-follon/fdir/issues/2))**

`fdir_report_fault()` used three separate port-sync critical sections for latch/health check, enqueue, and marking entity health failed. Concurrent reports for the same entity+reason could enqueue duplicates and burn bounded queue slots under fault storms.

- Latch check, enqueue, and `FDIR_HEALTH_FAILED` update now run under one held port sync
- Added `fdir_failure_queue_put_unsafe()` for callers already holding the lock

## Also included

- SEooC queue back-pressure section updated for the atomic report path
- Tests: `test_entity_register_rejects_restart_on_exhausted`, `test_report_fault_no_duplicate_enqueue_before_supervisor`

## Migrating from v1.0.0

No migration required. If you previously set `on_exhausted` to `FDIR_ACTION_RESTART`, pick a terminal action (`DEGRADE`, `UNAVAILABLE`, `SAFE`, or `REBOOT`) instead; registration will reject the old value.
