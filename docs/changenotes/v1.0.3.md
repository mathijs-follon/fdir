# v1.0.3

Bug-fix and documentation release. One small API addition.

[README](https://github.com/mathijs-follon/fdir/blob/main/README.md) | [API reference](https://github.com/mathijs-follon/fdir/blob/main/docs/api.md)

## Bug fixes

**Anomaly-ID namespace collision**

Entity anomaly keys use the high byte with bit 15 clear; subsystem keys set bit 15. Entity IDs >= 128 collided with subsystem-tagged IDs when `FDIR_ENTITY_CAP` was raised above 128. The library now rejects `FDIR_ENTITY_CAP > 128` at compile time.

**Health snapshot torn reads**

`fdir_health_snapshot()` still returns a live pointer (unchanged for compatibility). Added `fdir_health_snapshot_copy()` to copy health state under port sync for concurrent integrations.

## Also included

- `docs/threading.md`: subsystem query concurrency, health snapshot guidance, `get_now_ms` inside locked `fdir_report_fault`
- Test: `test_health_snapshot_copy`, `test_anomaly_id_entity_subsystem_namespaces`
- `examples/filecopy`: port `lock`/`unlock` via `pthread_mutex_t` for worker/supervisor threads

## Migrating from v1.0.2

- If you raised `FDIR_ENTITY_CAP` above 128, reduce it to 128 or lower, or fork the anomaly-ID macros.
- For multi-task health reads with a port lock, switch to `fdir_health_snapshot_copy()`.
